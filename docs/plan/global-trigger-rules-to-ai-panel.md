# 全局触发规则移到 AI 对话面板：更改方案

> 需求：把「回复与权限」页的**「高级规则」（即账号级/全局设置）**移到 AI 对话面板的
> **「触发方式」**卡里。回复与权限页继续负责「哪些群能回 + 单群例外 + 谁能回复」。
>
> 这是对上一轮 T0–T4 的**入口回调**：上一轮把触发方式全部收进「回复与权限」，
> 现在把**全局（账号级）那部分**搬回日常操作台，群级例外仍留在权限页。

---

## 1. 现状

| 位置 | 现在有什么 | 问题 |
|---|---|---|
| `/reply`（回复与权限） | 三个 tab：**群与私聊** / **谁能回复** / **高级规则**；「高级规则」= 账号专属规则摘要 + 编辑按钮（`PolicyRulesDialog`，`channelId=null`）+ 多账号插件分工提示 | 全局规则藏在二级 tab 里，日常想调「什么时候接话」要跳页 |
| `/ai`（AI 对话面板） | 「触发方式」卡 = 只读摘要 + 「去修改」跳 `/reply?tab=rules` | 只能看不能改，入口指向权限页二级 tab |

数据真相没有变化：全局规则存在 `channel_overrides` 的**账号层**（`channel_id=""`），
经 `GET /api/policy` 解析出 `resolved.config` + `sources`；群级覆盖在群行。
**因此本次改动是纯前端入口重组，不需要动领域模型、API、迁移。**

---

## 2. 目标形态

```
AI 对话面板（/ai）
├── 回复开关（已有：总开关 + 群聊/私聊只读 chip）
├── 触发方式  ← 变成「全局触发规则」的唯一编辑入口
│   当前生效：@ 或关键词（AI、助手）· 冷却 3s · 22:00-08:00 静音
│   来源：账号规则 / 默认（chips）
│   [编辑全局触发规则]   [去设置群例外 →]
├── 模型 / 人格 / 谁能回复（不变）
└── 更多设置

回复与权限（/reply）
├── 群与私聊（保留：账号默认开关、群列表三态、单群专属规则）
└── 谁能回复（保留：响应权限 / 拥有者 / 管理者 / 高危工具审批）
    ✗ 「高级规则」tab 删除
```

要点：
1. **全局规则唯一编辑器 = AI 面板「触发方式」卡**，点开复用现有抽屉
   （`PolicyRulesDialog`，`channelId=null`），内容含：触发方式（@ / 关键词 / @或关键词 /
   所有消息 + 概率 / 都不）、冷却、消息合并、免打扰、用户例外，以及**生效预览（值+来源）**。
2. 卡面**不内嵌大表单**（AI 面板是操作台，不是配置页）：只显示一行生效摘要 + 来源 chips
   + 两个按钮（编辑全局规则 / 去设群例外）。
3. 摘要数据**必须来自 `/api/policy`**（`resolved.config` + `sources`），不能像以前那样从
   `agent.draft.trigger_at/keyword` 推断——否则会和账号层覆盖、群级覆盖、双写旧键漂移。
4. `/reply` 删掉「高级规则」tab 后，页面副标题改为
   「哪些群能回、谁能触发；全局触发规则在 AI 对话面板」。

## 3. 交互与文案

### 3.1 AI 面板「触发方式」卡

```
触发方式                                     [编辑全局触发规则]
全局规则：什么时候接话、多快回、何时安静
────────────────────────────────────────────────────
当前生效   @ 或关键词（AI、助手） · 冷却 3s · 22:00-08:00 静音
来源       触发·账号规则   冷却·默认   免打扰·账号规则   （chips）
────────────────────────────────────────────────────
单个群可以不同：去「回复与权限」的群列表里点该群「本群专属规则」 →  [去设置群例外]
```

- 保存后**立即刷新卡面摘要**（抽屉关闭时重新拉 `/api/policy`）。
- 账号未连接时也能改（规则是本地库，不依赖协议端在线）。
- 卡面与抽屉的“继承值”同源（都读 `/api/policy`），避免“卡上说 A、抽屉说 B”。

### 3.2 `/reply` 页

- 删除 `v-tab value="rules"` 与对应 `v-window-item`（账号摘要卡、编辑按钮、插件分工提示）；
- 「群与私聊」的账号默认卡保留（群聊/私聊开关默认）；
- 深链兼容：`/reply?tab=rules` 不再有对应 tab →
  - `readTab()` 白名单去掉 `rules`，落回 `groups`；
  - 若 URL 带 `tab=rules`，进入时弹一次 toast：「全局触发规则已移到 AI 对话面板」+
    可选按钮跳 `/ai`；不阻塞使用。

### 3.3 「谁能回复」与「用户例外」的归属

- 「谁能回复」tab（响应权限 / 拥有者 / 管理者 / 高危工具审批）**留在 `/reply`**；
- `PolicyRulesDialog` 里的「用户例外（黑名单/白名单）」属于**全局触发规则**的一部分，
  跟随抽屉一起搬到 AI 面板入口，不再在 `/reply` 单独暴露（底层仍是账号层 permission 键，无迁移）。

## 5. 风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 老用户找「高级规则」 | 到 `/reply` 找不到 tab | 深链 toast + 页面副标题写明新位置；`/ai` 卡入口放在第二张卡，日常可见 |
| AI 面板变“配置页” | 操作台臃肿、768px 以下难用 | 卡面只放摘要 + 按钮；表单仍在抽屉里 |
| 摘要与群级覆盖不一致 | 用户以为全局改了所有群 | 摘要来源 chips 显示「账号规则」；文案注明“单个群可单独设置” |
| 抽屉组件跨目录复用 | 依赖 `components/policy/` | 允许（同一页面的规则组件），必要时给 `PolicyRulesDialog` 增加 `channelId=null` 的说明注释 |
| `/reply` tab 删除影响深链 | 旧书签落空 | `readTab()` 白名单 + `tab=rules` toast 兜底 |

## 6. 验收

1. `/ai` 触发方式卡：显示**来自 `/api/policy`** 的生效摘要与来源；点「编辑全局触发规则」能打开抽屉；
   在抽屉里把触发方式改成「所有消息 30%」，保存后卡面立即显示新值；`/reply` 的群行（选“继承”的群）
   触发方式同步变化。
2. `/reply`：没有「高级规则」tab；访问 `/reply?tab=rules` 落回「群与私聊」并弹出提示；
   「本群专属规则」仍可覆盖全局值。
3. 前端：`npm run typecheck` + `npm run build` 通过；`/ai`、`/reply` 在 1440/390 截图，
   `metrics.json` overflow 均为 0；抽屉打开态两种宽度均无横向溢出。
4. 后端回归：`tests/webui/test_policy_api.py`、`tests/domain/test_dialogue_policy.py` 全绿。
