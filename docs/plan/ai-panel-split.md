# AI 对话面板拆分方案（用户视角）

> 状态：**方案稿（待确认后实施）**
> 目标：把现在「AI 对话设置」这一个混合体拆清楚——**日常运营的面板** 与 **成体系的设置** 分开；
> 同时把「回复设置」和「权限管理」归一成一处，消灭「同一个问题要去两个页面找」。
> 不改任何配置键，只改信息架构（IA）、路由与页面归属，数据零迁移风险。

---

## 1. 现状问题（为什么必须拆）

当前侧栏「能力」下的 **AI 对话设置** 是一个折叠分组，里面塞了 5 个子页：

| 子页 | 实际内容 | 用户困惑 |
|---|---|---|
| 概览 | 5 张分区入口卡 | **纯导航页**：点进去还要再点一次，没有信息量；与侧栏重复 |
| 基础配置 | 启用 AI 回复、群聊/私聊开关、提示词方案、人格选择 | 这是"日常最常改的东西"，却藏在二级菜单里 |
| 权限管理 | 响应权限档位、拥有者/管理者名册、高危工具审批 | **与「回复设置」高度重叠**：一个管"谁能触发"，一个管"哪些群能触发"，用户不知道去哪个 |
| 对话行为 | 触发设置（@/关键词）、消息合并、回复打断 | 触发设置是高频项，和权限、场景是一组问题，却被拆到另一个子页 |
| 会话管理 | 上下文窗口、群历史、压缩 | 低频深度参数，放这里合理 |
| 高级功能 | 图片/联网/工具执行/缓存 | 低频深度参数，放这里合理 |

一句话：**"面板该有的（状态 + 高频开关）"和"设置该有的（低频参数）"混在一起，而且"谁能回/在哪回/什么时候回"被拆成三个入口。**

---

## 2. 拆分原则（用户的三个问题）

把机器人的"回复"这件事，按用户脑子里的三个问题归类：

1. **「现在能不能回、回得怎么样？」** → 一眼看状态、随手开关 → **AI 对话面板**
2. **「它在哪些群、对谁、什么条件下回？」** → 范围与权限规则 → **回复与权限**（归一）
3. **「回复的细节怎么调？」** → 时序、上下文、高级能力 → **AI 设置**（低频、成体系）

并约定一条硬规则，避免又长出"两处都能改"的老毛病：

> **每个配置字段只有一个"编辑主入口"，其他页面只能显示摘要 + 跳转。**

---

## 3. 目标信息架构

```
能力
├── AI 对话面板            /ai                ← 新页面（替代原「概览」，高频操作台）
├── 回复与权限            /reply             ← 原「回复设置」+ 原「权限管理」合并
├── AI 设置（分组）        /ai/settings/*     ← 原「AI 对话设置」去掉概览/基础配置/权限/触发
│   ├── 对话行为          /ai/settings/behavior
│   ├── 会话管理          /ai/settings/session
│   └── 高级功能          /ai/settings/advanced
├── 人格设定              /personas
├── 功能插件              /modules
└── 配置包                /bundles
```

- **移除**：原「AI 对话设置 → 概览」页（`/agent` 首页）。
- **改名**：「AI 对话设置」分组 → 「AI 设置」，只保留 3 个深度设置页。
- **归一**：「回复设置」(群/私聊范围) + 「权限管理」(权限档位/名册/高危审批) → 「回复与权限」一页。

## 4. 三个页面的用户视角设计

### 4.1 AI 对话面板（`/ai`）—— 每天打开的那一页

**回答的问题**：现在能不能回？回得怎么样？常用的开关在哪？

```
┌ 头部：当前账号（所有配置按账号保存）    [诊断] [发测试消息] ┐
│ 状态：● AI 回复已开启 | 模型就绪 | 人格：群聊搭子 | 最近错误：无 │
├──────────────────────────────────────────────┤
│ ① 回复开关                                   │
│    [总开关] 启用 AI 回复                      │
│    [群聊] 在群里回复      [私聊] 在私聊里回复   │
├──────────────────────────────────────────────┤
│ ② 触发方式（什么时候回）                       │
│    [ ] 被 @ 时回复                            │
│    关键词：[AI] [助手]  （每行一个；留空=不按关键词）│
│    摘要：当前 = 被 @ 或命中关键词时回复          │
├──────────────────────────────────────────────┤
│ ③ 谁能让它回复（摘要，只读）                   │
│    当前档位：普通成员及以上   [去调整 →]        │
│    拥有者 1 人 · 管理者 2 人                   │
│    高危工具审批：关闭                          │
├──────────────────────────────────────────────┤
│ ④ 人格与模型（摘要 + 跳转）                    │
│    当前人格：群聊搭子  [更换/编辑 →]            │
│    模型池：2 个模型，主模型 deepseek-chat       │
├──────────────────────────────────────────────┤
│ ⑤ 最近活动（可选）                             │
│    最近一条回复 / 最近一次失败原因  [查看日志 →] │
└──────────────────────────────────────────────┘
底部：[更多设置 →]（跳 AI 设置）
```

**可编辑字段（唯一编辑入口）**：`agent.enabled`、`group_enable`、`private_enable`、`trigger_at`、`trigger_keyword`、`prompt_preset`、`persona_preset_id`。
**只读摘要 + 跳转**：权限档位/名册/审批（→ 回复与权限）、模型池（→ 模型服务）、人格内容（→ 人格设定）。
保存沿用现有 2 秒自动保存 + 保存状态 chip，不新造一套。

### 4.2 回复与权限（`/reply`）—— "在哪回、回谁、按什么规则"

**回答的问题**：这个号在哪些群/私聊能说话？谁能触发它？群级例外怎么设？

用三个 Tab 装下原来散在两处的全部内容：

| Tab | 内容 | 来源 |
|---|---|---|
| **群与私聊** | 账号默认（跟随面板设置/允许/不允许）、群列表三态开关（允许/禁止/沿用）、搜索、批量、静音到几点 | 原「回复设置」 |
| **谁能回复** | 响应权限档位（所有人/成员/群管/群主/管理者/拥有者）、拥有者 QQ 名册、管理者 QQ 名册、高危工具审批开关 | 原「AI 对话设置 → 权限管理」 |
| **高级规则** | 逐群/账号级的触发与回复规则（原「高级规则」对话框内容，改为页内区域） | 原「回复设置 → 高级规则」 |

**归一化的语义**（写进页面副标题，让用户不再困惑）：

> 面板管"默认开不开、怎么触发"；这里管"逐群/逐人的例外"——群默认跟随面板的群聊开关。

- 权限档位与名册只在这里编辑（面板只显示摘要）。
- 「群与私聊」的账号默认三态里，「跟随」指向面板的 `group_enable`，保持现有语义不变。

### 4.3 AI 设置（`/ai/settings/*`）—— 一年调几次的深度参数

| 子页 | 内容 | 变化 |
|---|---|---|
| 对话行为 | 消息合并等待、回复打断 | **移出**「触发设置」（去面板） |
| 会话管理 | 上下文窗口、群历史、压缩 | 不变 |
| 高级功能 | 图片/动图、联网搜索、工具执行、工具日志、模型缓存 | 不变 |

页头统一：当前账号 chip、保存状态、返回面板；**不再有二级"概览"页**。

## 5. 字段级迁移映射（单一真相清单）

| 现有字段/入口 | 现在位置 | 新位置（唯一编辑入口） |
|---|---|---|
| `agent.enabled` | 基础配置 | **面板** ① 回复开关 |
| `group_enable` / `private_enable` | 基础配置 | **面板** ① 回复开关（群级"跟随"引用它） |
| `prompt_preset` | 基础配置 | **面板** ④ 人格与模型（系统提示词风格） |
| `persona_preset_id` | 基础配置 | **面板** ④ 人格与模型 |
| `trigger_at` / `trigger_keyword` | 对话行为 → 触发设置 | **面板** ② 触发方式 |
| `permission` | 权限管理 | **回复与权限** → 谁能回复 |
| `agent_owner_list` / `agent_manager_list` | 权限管理 | **回复与权限** → 谁能回复（面板只显示人数摘要） |
| `tool_approval_enable` | 权限管理 | **回复与权限** → 谁能回复 |
| 逐群三态 / 账号默认 / 批量 / 静音 | 回复设置 | **回复与权限** → 群与私聊 |
| 高级规则 | 回复设置 → 高级规则弹窗 | **回复与权限** → 高级规则 |
| `message_debounce_*` / `reply_cooldown` / `interrupt_*` | 对话行为 | **AI 设置 → 对话行为** |
| 会话/压缩/高级功能全部字段 | 会话管理 / 高级功能 | **AI 设置 → 对应子页**（不变） |
| 概览页 5 张入口卡 | AI 对话设置 → 概览 | **删除**（侧栏已承担导航） |

## 7. 实施拆解与工作量

| 1 | 配置分区改造：`config_partition.py` 去掉 basic/permission 页与 behavior.trigger 组；新增 `PANEL_KEYS`（面板字段清单，仍引用 `SCHEMA` 单一真相）并生成 `ai-panel.json`；regenerate `sections.json`（5 页 → 3 页）；同步更新 `test_config_partition` / `test_agent_section_contract` / `test_architecture_layout` 的页面数与字段数断言 | 0.5 天 |

## 8. 验收标准

1. 新用户从「账号管理」到"开启群聊回复"≤ 3 次点击（面板一屏内完成），不需要进二级菜单。
2. 问"为什么这个群不回"：在「回复与权限」一处能看到群开关 + 账号默认 + 权限档位；在面板能看到总开关与触发方式摘要。
3. 任一字段只有一处可编辑：面板/回复与权限/AI 设置不出现同一字段的第二个输入框（架构测试可用 `ai-panel.json` ∩ `sections.json` = ∅ 来守）。
4. 旧书签（`/agent/basic`、`/agent/permission`、`/policy` 等）全部重定向到新位置，不出现白屏。
5. `pnpm typecheck`、`pnpm build`、全量 pytest、两道文案/SFC 闸门全绿；浅色/暗色实机截图核对。
