# 触发方式 × 回复与权限：集成方案（规划）

> 目标：把「触发方式」从 Agent 面板的独立配置，收进**同一张「回复与权限」面板**：
> 用户在同一个地方看到「谁能触发 → 什么条件触发 → 触发后怎么回 → 什么时段不回」，
> 并且默认（账号/场景）与例外（单个群）的层级关系一眼可读。

---

## 1. 现状盘点（为什么现在算"半集成"）

触发相关能力**后端已经是一张表**（`channel_overrides` + 分层解析），前端却有三个入口：

| 入口 | 位置 | 管什么 | 问题 |
|---|---|---|---|
| 「回复开关」卡 | Agent 面板 | 账号级 `group_enable` / `private_enable` | 与 `/policy` 的"账号默认场景"重复 |
| 「触发方式」卡 | Agent 面板 | 账号级 `trigger_at` / `trigger_keyword` | 与 `/policy` 规则对话框重复；看不到"这个群最终是什么触发方式" |
| `/policy` 页（权限与回复） | 侧栏 | 账号/场景默认 + 群矩阵 + 规则覆盖（触发方式/关键词/冷却/合并/免打扰/用户例外） | 触发方式藏在"规则"弹窗里，群行上只显示回复三态；没有生效预览 |

后端解析链（已是单一真相）：

```
账号级 binding / agent 配置  →  场景层（__group__ / __private__）  →  群级 channel_overrides
                              （越具体越优先）
```

`SCOPE_OVERRIDABLE["agent"]` 已含：`trigger_at`、`trigger_keyword`、`reply_cooldown`、
`message_debounce_seconds`、`message_debounce_max_wait`、`interrupt_enable`、`quiet_hours`；
权限键 `role_min / user_mode / user_list` 同样分层。

**结论：能集成，而且不需要改数据模型，只需要"收口入口 + 补齐表达"。**

---

## 2. 目标模型（一句话）

> 把「触发」变成回复策略里的**第一等字段**：与"是否允许回复"同屏配置，
> 默认值给小白，例外给每个群，生效值可预览。

### 2.1 统一字段表

| 键 | 类型 | 默认 | 可覆盖层 | 说明 |
|---|---|---|---|---|
| `enabled` | 三态 bool | 继承账号开关 | 场景 / 群 | 已有（矩阵三态） |
| `trigger_mode` | enum | `at` | 场景 / 群 | 新增：`at` / `keyword` / `both` / `all` / `none` |
| `trigger_keyword` | string_list | `[]` | 场景 / 群 | 已有；`keyword`/`both` 时生效 |
| `trigger_probability` | int 0–100 | `100` | 场景 / 群 | 新增：仅 `all` 用（"每条消息都有 X% 参与"） |
| `reply_cooldown` | int 秒 | `0`（无冷却） | 场景 / 群 | 已有 |
| `message_debounce_seconds` / `_max_wait` | int 秒 | `0` / `15` | 场景 / 群 | 已有 |
| `quiet_hours` | `"HH:MM-HH:MM"` | 空 | 场景 / 群 | 已有 |
| `role_min` / `user_mode` / `user_list` | enum/list | 见权限设计 | 场景 / 群 | 已有 |

**归一规则（兼容旧配置）**：读 `trigger_mode` 缺省时由旧键折算——
`trigger_at && keyword`→`both`、`trigger_at`→`at`、`keyword`→`keyword`、否则 `none`；
写新键时同时回写 `trigger_at`/`trigger_keyword` 保持旧脚本/旧前端可读（一个过渡期）。

### 2.2 解析优先级（必须可见）

```
群级 channel_overrides（有值才覆盖）
  ↑
场景层 __group__ / __private__（有值才覆盖）
  ↑
账号级 binding / agent 配置（默认值）
```

面板上每个字段都要能显示"当前值来自哪一层"（复用 `resolved` 里的 source 语义）。

### 3.1 点开一行的「规则」抽屉（覆盖编辑，替代现在的弹窗）

```
┌ 水友群 · 规则 ────────────────────────────────┐
│ 允许回复   ( 继承 | 允许 | 禁止 )               │
│                                                │
│ 触发方式   ( 继承 | @ | 关键词 | @或关键词 | 所有消息 | 都不 )│
│   触发词   [摸鱼] [下班] + 添加                  │
│   概率     ——（仅"所有消息"可调） [====|--] 30%  │
│                                                │
│ 冷却       [ ] 继承   3 秒                      │
│ 消息合并   [ ] 继承   0 秒 (最长 15s)            │
│ 免打扰     [x] 覆盖   23:00 - 07:00             │
│ 用户例外   ( 继承 | 黑名单 | 白名单 )  [名单]    │
│                                                │
│ 每项左侧都有"继承"开关：关掉才写群级覆盖。        │
│ 右侧灰字 = 当前继承值，避免"留空不知道会怎样"。    │
│                        [取消]  [保存]           │
└────────────────────────────────────────────────┘
```

要点：
- **留空/继承必须显式**（checkbox），而不是"留空就继承"的隐式约定——小白看不懂空值。
- 关键词用 chips 输入；概率只在"所有消息"时出现（其他模式隐藏，减少误配）。
- 免打扰用时间范围选择器，带"跨零点"提示。
- 保存逐项写入 `channel_overrides`，与现有 API 一致；保存后**就地刷新该行生效值**。

## 4. 两种操作方式（对应两类用户）

### 4.1 小白路径（默认 90% 场景）

1. 进「回复与权限」→ 顶部账号默认里选：**群聊：只回 @ 我的消息**（预设三个选项：
   「只回 @」「@ 或关键词」「所有消息都参与」）。
2. 群列表默认全部「继承」→ 不需要逐个配。
3. 不想让某个群说话 → 该行开关点「禁止」。
4. 临时静音 → 群内发 `#llm mute 2h` 或行内「静音」按钮（已有）。

### 4.2 高级路径

1. 点某行「规则」→ 抽屉里按需覆盖触发方式/关键词/概率/冷却/免打扰/用户例外。
2. 「生效预览」核对每个键的来源，确认没有"以为继承了其实被群级覆盖"。
3. 批量：选中若干群 → 统一设为允许/禁止/继承；或统一覆盖率。

### 4.3 入口收敛

- Agent 面板的「回复开关」「触发方式」两张卡 → 改为**只读摘要卡**（显示账号默认值 + 「去权限与回复配置」按钮），
  不再作为第二份编辑器（与现有权限入口链接卡同一模式）。
- 群内 `#llm status` 输出的内容与面板「生效预览」同源（已有 `dialogue_policy_service.resolve`）。

## 5. 后端改造清单

| 层 | 改动 | 说明 |
|---|---|---|
| `app/domain/dialogue_policy.py` | 新增 `trigger_mode` / `trigger_probability` 到 `SCOPE_OVERRIDABLE`；加 `normalize_trigger_mode()` 与旧键折算；`validate_override_values` 校验枚举/范围/关键词去空 | 纯函数，先测 |
| `app/application/dialogue_policy_service.py` | `resolve()` 返回值加 `trigger_mode`（折算后）与逐键 `sources`；`update()` 支持新键 + 回写旧键；`matrix()` 行内返回生效触发方式与来源 | API 合同扩展，向后兼容 |
| `app/agent/loop/pipeline.py` | 触发判定改为读解析后的 `trigger_mode`（兼容旧键）；`all` 模式按 `trigger_probability` 随机（可注入 RNG 便于测试） | 行为变化点，需回归测 |
| `app/webui/api/policy.py` | `GET /policy/matrix` / `GET /policy` 返回新字段；`POST /policy` 接受新键 | 保持旧字段不变 |
| `app/application/dialogue_policy_migration.py` | 迁移时把 agent 配置里的 `trigger_at`/`trigger_keyword` 落到账号级 override，保证升级后行为不变 | 幂等 |
| `app/agent/config_partition.py` | Agent 面板「触发方式」组标记为"已迁出"（不再渲染编辑控件） | 前端按 sections 生成 |
| 前端 | `PolicyPage.vue` 加列/预览/抽屉；`PolicyRulesDialog.vue` 改抽屉 + 显式继承开关 + 概率；Agent 侧卡片改摘要 | 需按 AGENTS 前端规范做 1440/390 双尺寸截图 + metrics |

## 6. 兼容 / 迁移

- 旧配置：`trigger_at`/`trigger_keyword` 继续可写可读；`trigger_mode` 缺省时折算。
- 旧前端/脚本：`POST /policy` 不传新键时保持原语义（不覆盖）。
- 迁移：启动时一次性把 agent 配置里的触发键写进账号级 override（幂等标记复用 R4 的 flag）。
- 回滚：删掉 override 行即回到账号默认；新键独立存储，不影响旧字段读取。

## 7. 验收与测试

| 层 | 用例 |
|---|---|
| domain | 旧键→`trigger_mode` 折算表（4 种组合）；非法枚举/概率拒绝；关键词去空 |
| policy service | 三层解析优先级（账号→场景→群）；`sources` 正确；批量设置；显式继承清除覆盖 |
| pipeline | `at`/`keyword`/`both`/`all`（概率 0/100/注入 RNG）四类触发；`none` 不触发；权限禁止优先于触发 |
| API | matrix 行含生效触发方式与来源；旧 payload 仍工作 |
| 前端 | `pnpm typecheck` + `build`；1440/390 截图，`overflow=0`；切换行内三态无位移（≤1px）；抽屉打开/关闭无跳变 |

## 8. 阶段拆分

| 编号 | 内容 | 提交 |
|---|---|---|
| **T0** | 领域模型：`trigger_mode` / 概率 + 旧键折算 + 校验（纯函数 + 测试） | `feat(policy): add explicit trigger mode to the policy model` |
| **T1** | 服务/API：解析返回 `trigger_mode` + `sources`；matrix 行补齐；兼容旧键 | `feat(policy): expose resolved trigger mode and value sources` |
| **T2** | 触发判定：pipeline 改读 `trigger_mode`（含概率，RNG 可注入） | `feat(agent): trigger messages by the resolved trigger mode` |
| **T3** | 前端面板：群列表加"触发方式/免打扰"列 + 生效预览 + 抽屉式规则编辑 + 显式继承开关 | `feat(webui): merge trigger configuration into the reply and permission page` |
| **T4** | 入口收敛 + 迁移 + 文档：Agent 面板两卡改摘要；启动迁移；README/设计文档同步 | `refactor(webui): point agent trigger cards at the unified policy page` |

判定"完成"的标准：面板上**不再需要去 Agent 面板就能配触发方式**；任一群的
"为什么这条消息会/不会触发"能在生效预览里逐键看到来源。

## 9. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 概率触发导致回复不可复现 | 用户觉得"时好时坏" | 概率默认 100；只在显式选 `all` 时可调；`#llm status` 显示当前概率 |
| 旧前端仍写 `trigger_at`/`trigger_keyword` | 与新字段漂移 | 服务端写入时双写；读取时折算；过渡期保留旧字段 |
| 群级覆盖太多导致"以为继承" | 排障困难 | 生效预览 + 行内"覆盖"标记 + 抽屉里灰字继承值 |
| 前端改动大 | 回归面广 | 按 T3/T4 拆分提交；截图 + metrics 验收 |
