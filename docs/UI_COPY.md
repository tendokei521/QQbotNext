# 界面文案规范

一条界面文字只回答两件事：**这个开关干什么、什么时候该动它**。不是设计说明，不是变更日志。

## 1. 句式

`做什么。什么时候动。代价（真有才写）。`

| 正例（仓内真实文案） | 好在哪 |
|---|---|
| `开关只影响当前账号`（功能插件页副标题） | 一句话划清边界 |
| `填一次 Key，所有账号共用`（模型服务页副标题） | 收益 + 前提 |
| `0 = 几乎不贴；1 = 每 3~5 轮一次（默认）` | 档位带默认值 |

反例：`本次迁移后接管原槽位`（黑话）、`注意：这个选项很重要`（说教零信息）、`history_rounds`（变量名当文案）、`上面的「高级选项」里改`（跨控件指路，布局一变就失效）。

## 2. 长度

| 位置 | 上限 | 依据 |
|---|---|---|
| `label` / `title` / `placeholder` / `hint` / `alt` 字面量 | 40 汉字 | Vuetify hint 只有两行小字 |
| `.vue` 模板文本，按 `。；！？` 切句 | 60 汉字/句 | 一句读不完就该拆段或进文档 |

超限先拆字段或改写，不要压成电报体。

## 3. 禁止词（与 `test_dashboard_copy.py` 的 JARGON 列表一致）

| 类别 | 禁 | 改成 |
|---|---|---|
| 版本/框架 | `v3`、`v4`、`P4`、`P5`、`legacy`、`schema` | 不写；确需说明用「旧版配置」 |
| 内部过程 | 迁移、接管、闸门、哨兵、装配、槽位、落库、上游、后端、框架级、此前、曾经、历史上 | 上限 / 限制 / 开关 / 保存；时间自指直接删 |
| 抽象名词 | 接口化、模块化、语义化、工件、枚举 | 换成具体名词 |
| 故障与兜底 | 抖动、防抖、兜底 | 消息合并等待 / 默认值 |
| 裸标识符 | `history_rounds`、`max_tokens`、`sub_type` | 中文描述 |
| 旧页面名 | System Tools / MCP Tools / OneBot Tools / Module Tools / Tool 管理 / Provider 预设 / Agent 面板 / 群聊权限 / AI 对话设置 / 功能模块 / 预设中心 | 见 §4 |

## 4. 术语表（一个概念，全站一个词）

| 概念 | 现在用的词 | 出现处 | 不要用 |
|---|---|---|---|

## 5. `0` 的写法

统一 `0 = X`（等号两边各一个空格），含义写全：`0 = 不提醒`、`0 = 不启用（按条数）`、`0 = 不限制，会明显增加消耗`、`0 = 每条都立刻回`。
不要 `0=关闭`、不要 `0 表示不限制`，也不要让 `0 =` 后面空着。

## 6. 闸门

```powershell
venv\Scripts\python.exe -m pytest tests\architecture\test_ui_copy.py tests\architecture\test_dashboard_copy.py -q
```

| 闸门 | 守什么 |
|---|---|
| `test_ui_copy.py` | 后端 `config_schema.py`（本体 + `app/plugins/*/`）的 `description`：长度、黑话、裸变量名、口语、指路、`0` 写法；另查 `components/agent/sections/*.vue` 的 `v-card-text` 与「定时任务/主动消息跟着一起停」这类过时说法 |
| `test_dashboard_copy.py` | `src/**/*.vue` 的模板文本、`label/title/placeholder/hint/alt` 字面量、表达式里的中文字面量；加 `agent/sections.json`、`agent/ai-panel.json` 的标题 |

`<script>` / `<style>` 不扫（代码与注释不算文案）。失败信息给 `文件:行号 + 命中词 + 原文片段`。
说明文字统一用 `src/components/common/HintText.vue`（12.5px、60% 透明度），不要自写 `.field-desc` 或另调透明度的 `text-caption`。
