> 本文只负责：规定界面上每一句话怎么写（长度、句式、禁用词），以及为什么这么规定。

# 界面文案规范

界面上的每一句话只承担一个职责：**让用户知道这个开关干什么、什么时候该动它**。
它**不是**设计文档、不是变更日志、不是给同事看的备忘录。

---

## 1. 句式（三段式，能省则省）

```
做什么。什么时候该开。代价（如果真有）。
```

示例：

> 注入当前对话焦点，让模型知道「那条」「刚才的」指什么。

> 对每张图都探测是否为动图。动图识别不到时可开启，代价是多一次下载。

**不要**写"为什么当初这么设计"——那属于 `docs/AGENT_CONFIG.md`。

---

## 2. 长度：≤ 40 个汉字

Vuetify 的 `hint` 是两行小字。超过 40 字实际没人读，等于没写。
如果 40 字说不完，说明这个字段该拆，或者说明该进文档。

闸门：`tests/architecture/test_ui_copy.py::test_descriptions_are_short_enough`

---

## 3. 禁止词表

### 内部黑话（用户不知道也不需要知道）

| 禁用 | 改成 |
|---|---|
| v3 / v2 / P4 / P5 / 接口化 / 模块化 | —— |
| 迁移 / 接管 / 槽 / 闸门 / 哨兵 | "上限""限制""开关" |
| 此前 / 曾经 / 历史上 / 旧版 | —— |
| 仿 AstrBot / 对齐 AstrBot / legacy | "标准""旧版" |

### 变量名与协议字段

`history_rounds`、`max_tokens`、`get_chat_history`、`expand_*`、`sub_type`
→ 一律换成中文描述。看代码的人才需要这些名字，界面上不需要。

### 口语与说教

`这个 Bot`、`你自己`、`咱们`、`免得`、`别让`、`说白了`、`注意：`

### 跨控件指路

`上面的「xx」`、`下面的「xx」`、`上文提到`
→ 这是**布局问题**的病征。用布局解决，别用文案。

---

## 4. `0` 的写法

统一写成 **`0 = X`**（带空格），且必须写明含义：

| 场景 | 写法 |
|---|---|
| 开关类 | `0 = 关闭` / `0 = 立即请求` |
| 限额类 | `0 = 不限制` / `0 = 不限` |
| 重试类 | `0 = 不重试` / `0 = 不提醒` |
| 档位类 | `0 = 几乎不贴` |

不要写 `0=关闭`、`0 表示不限制`（同一个意思三种写法会让用户怀疑是不同东西）。

---

## 5. 可以用的术语

技术产品不必回避专业词，以下不算黑话：

`token`、`LLM`、`Provider`、`流式`、`指代`、`embedding`、`知识库`、`上下文`、
`工具调用`、`模态`、`QT`/`QQ` 号。

判断标准：**用户买这个功能时就已经懂的词**可以用；**只有读过源码才懂**的词不能用。

---

## 6. 设计缘由放哪

被删掉的"为什么这么设计"不丢，统一归档到：

- `docs/AGENT_CONFIG.md` —— 每个字段的设计意图、历史原因、与第三方框架的对应关系
- `docs/MODULE_DEV.md` —— 模块侧行为

---

## 7. 闸门

```bash
pytest tests/architecture/test_ui_copy.py -q
```

五条规则：长度、黑话、裸变量名、口语/指路、`0` 写法。
新增字段时如果文案不合规，测试会直接指出是哪一条。
