# 指代消解（Referent Resolution）设计定稿

> 状态：**P0~P4 已完成并测试通过**（`app/llm/focus.py` / `referent.py` / `context_tools.py`）。
> 触发案例：`group_466052056` 2026-09-18 21:37「那你能做到消息里的那个样子吗」——
> 纯回指句，模型选了群里最新的转发（1000165352）而不是上一轮讨论过的那条（576048059）。

## 1. 问题本质

用户说"那个/那条/消息里的那个样子"时，要模型回答出一个**具体对象**，需要三件事同时成立：

1. **知道说的是什么**（指代类型：消息 / 人 / 内容）；
2. **知道指向哪个**（在多个候选里定出目标）；
3. **拿到指向的内容**（取回 + 留痕）。

当前失败**不是模型笨**，而是代码没把"上一轮在讨论什么"留在它眼前：

| 断点 | 位置 | 后果 |
|---|---|---|
| 工具结果不进会话历史 | `session.py:288` `add_message` 只存 user/assistant；`tool_loop` 的 `role=tool` 只活当轮 | 上一轮展开的内容这一轮消失，只能看自己一句概括 |
| 标记无状态迁移 | `group_context._segment_text` 只有"未展开"一态 | 读过也不留痕，重复读、反复读 |
| 无相对位置能力 | `context_tools` 只接受绝对 id | "上一条消息"无法表达 |
| 候选平铺无权重 | `build_group_env_text` 把 8 个 `【未展开:…】` 等权列出 | 模型只能挑"最新/最显眼"的 |
| 无指代规则 | `prompt.py` 无对应条目 | 指代不明时无处置策略 |

## 2. 设计红线

**能由代码确定性算出来的，绝不交给模型决策**：回复段、@、展开历史、时间邻近，全部可算。
模型只负责"真歧义"的最终裁决。收益不只是准，还有快——21:37 那轮模型"思考到决定调工具"
花了 10.9 秒，确定性预取可省掉。

## 3. 分层

```
L0 事实层  会话焦点表（focus.py）        —— 谁刚被讨论过（代码维护）
L1 解析层  指代判定 + 候选生成（referent.py）—— 零模型成本的规则
L2 决策层  排序；确定就预取，歧义就双取
L3 取回层  fetch_entity + 状态三态迁移
组装层     焦点行 + 已展开摘要 + 未展开标记（带权重，不平铺）
```

### L0 会话焦点表（`app/llm/focus.py`）

形态照抄 `nicknames.py`（模块级有界字典 + TTL），写入点全部是确定性钩子：

| 写入时机 | 落点 | 权重 |
|---|---|---|
| 本轮消息 reply 某条（显式指向） | `enhance.collect_user_context`（已有 `reply_id`） | 5.0 |
| 本轮文本里出现 `【未展开:引用X】` | 同上 | 4.0 |
| 本轮 `expand_*` 取回的 id | `context_tools` 成功回调 | 3.0 |
| 本轮 @ 对象 / 私聊对方 | 同上 | 2.0 |
| 背景窗口内出现过的 id | 渲染层登记（弱候选） | 0.5 |

```python
@dataclass
class FocusItem:
    ref: str          # 消息 id / QQ
    kind: str         # "message" | "user"
    label: str        # "合并转发576048059"
    summary: str = "" # 取回过才有：一句话摘要（≤80 字）
    source: str = ""  # reply | expand | at | window
    ts: float = 0.0
    turn: int = 0

# 显著性 = 来源权重 + 时间衰减（0.5 ** 轮差）；公式写死，不做参数玄学
```

**焦点表存摘要，不存原文**——这样"上一轮讨论过的内容"能低成本随每轮注入一行，
且不污染会话历史（比把工具结果写进历史干净）。

### L1 指代判定表（`app/llm/referent.py`）

规则保守（宁可多给候选），风格对齐 `_HISTORY_INTENT_RE` / `_ENV_INTENT_RE`：

| 话语形态 | 例子 | 指向 | 置信度 | 动作 |
|---|---|---|---|---|
| 显式回复 | `[reply:576048059]` | 该消息 | 确定 | 框架预取 |
| 显式 @ | `@123` | 用户 123 | 确定 | 登记焦点（人） |
| 相对位置 + 名词 | "上一条消息""刚才那张图" | 窗口内第 N 条 | 高 | 预取最近 1~3 条 |
| **纯回指**（无新实体、无 id） | **"那你能做到消息里的那个样子吗"** | **焦点表最新活跃项** | 中 | 预取焦点项；并列则双取 |
| 话题回指 + 名词 | "那个视频""那个转发" | 焦点同类项 ∪ 窗口同类项 | 中 | 双取 + 说明理解 |
| 人物指代 | "他是谁""这个人是谁" | 焦点人 ∪ 本轮发送者/@ | 中 | 预取成员信息 |
| 无指代 | "在吗""今天天气" | — | — | 不动作 |

要点：**"纯回指"的识别特征 = 整句没有任何新实体/id**；代词不做跨句语法分析，只走
"焦点优先"这一条保守规则。

### L2 决策层

```
确定/高  → pre_request 阶段框架直接预取（模型无感，省一轮推理）
中/多候选 → referent_ambiguous_policy:
    fetch_all（推荐，符合"全能 bot 不忽视、正常处理"的定位）→ Top-2 都取，标注"用户可能指 A 或 B"
    focus_first → 只取焦点最高项
    ask         → 让模型先确认
无指代   → 不动作
```

`fetch_all` 的边际成本只是一次内部并发调用，而猜错要付整轮答非所问 + 用户重问的代价。

### L3 取回与三态组装

状态迁移（解决"待读取 → 读取过 → 重读取"）：

```
待读取（本会话没取过）  【未展开:合并转发576048059】
读取过（取过，有摘要）  【已展开:合并转发576048059 → 小鳥遊ホシノ: 📺《学校的8种违法行为》…】
本轮已给出正文          （不再出现标记，正文在 tool 结果/预取块里）
```

- 登记表并入 `focus.py`（`FocusItem.summary` + `expanded_refs()`）；
- **工具/预取入口先查登记**：命中返回"本会话已展开过：<摘要>"，**零 API 调用**；
- 渲染时查登记决定三态（`group_context.ExpandedRefs` + `lookup_expanded`）；
- 取回时顺手产出**一句话摘要**（转发取前 1~2 条 + 类型标签），同时喂给焦点表；
- 公共 API：`fetch_entities(ctx, users=…, messages=…)` / `fetch_recent(ctx, count)` →
  `EntityResult(blocks, partial, refs)`（并发、条数/字符预算、失败如实汇报）。

### 组装层：焦点行（实际产物）

```
当前对话焦点（最近被讨论的优先）：
1. 合并转发576048059 —— 上一轮讨论过的：成人向对话记录（当时拒绝复述）
2. 合并转发1000165352 —— 本轮群里出现过的：（内容还没取回来）

（这句话没有直接指明对象，按“焦点优先 + 位置邻近”理解为：讨论过的 合并转发576048059、
  群里出现过的 合并转发1000165352；最近 2 条消息）

（下面这些内容已经替你取好了，直接用来回答即可）
第 1 近的消息（id 1000165352）：来自 小鳥遊ホシノ(3569937952)；合并转发内容：…《学校的8种违法行为》
【消息 576048059】成人向对话记录（当时拒绝复述）（本会话已展开过）；relation：指定展开的消息
```

差别：候选从"8 个等权 id"变成"2 个带来源、带顺序、带摘要的对象"；
且焦点那条命中登记 → **零 API 调用**（实测底层只发生 1 次 history + 1 次 forward）。

## 4. 提示词（三条，条条能被代码兑现）

见 `prompt.PROACTIVE_REFERENT_LINE`（由 `referent_prompt_enable` + `referent_resolve_enable`
+ `expand_recent` 是否可用三重裁剪）：

```
- 环境块里的「当前对话焦点」列出最近被讨论过的对象及其摘要：用户说"那个/那条/刚才说的/
  那个样子"这类回指时，优先指焦点里最新的那条，而不是群里时间上最新的消息。
- 候选不止一个、你不确定用户指哪个时：先用 expand_recent 看清最近两条（必要时把"上一轮
  讨论过的那条"和"最近一条"一起取回）再判断，不要只挑一条就答；回答时说明你按哪条理解。
- 用户说"上一条消息/刚才那条"这类按位置指代时用 expand_recent，不需要 id。
```

（"已展开的不必重复取"由 `PROACTIVE_UNRESOLVED_LINE` 承担。）

## 5. 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `referent_resolve_enable` | True | 指代消解总开关（焦点表 + 预取 + 焦点行） |
| `referent_prefetch_enable` | True | 确定性预取 |
| `referent_ambiguous_policy` | `fetch_all` | `fetch_all` / `focus_first` / `ask` |
| `referent_prefetch_max` | 2 | 一轮最多预取几个候选 |
| `referent_focus_ttl` | 1800 | 焦点项存活秒数 |
| `referent_focus_max` | 12 | 焦点表上限 |
| `referent_prompt_enable` | True | 指代解析提示行 |

## 7. 验收指标

- 回放 21:37：预取目标为 576048059 + 1000165352（焦点那条命中登记，零 API）；
- 同一 id 本会话只取一次（重复读取率 → 0）；
- 首字延迟下降（省掉"模型决定是否调工具"的推理段）；
- prompt 里平铺的裸 `【未展开】` 项数量下降。
