# QQBot Next 2.0

一个能自己"活"在 QQ 群里的机器人框架：多账号、多模型、有人格、会记人、会看群、能自己决定什么时候开口。

它不绑死在某一个模型上，也不要求你会写代码——装好、配一个模型、选一个人格，就能在群里聊天。
想扩展的时候，插件（模块）体系让你用几十行 Python 加一个新能力。

---

## 这个程序能做什么

| 能力 | 说明 |
|---|---|
| **多账号** | 一个进程管多个 QQ 号，每个号独立配置、独立模型、独立人格，可单独启停 |
| **接自己的模型** | OpenAI 兼容 / OpenAI Responses / Anthropic / Gemini 四种接口格式；一个号可用多个模型，主模型失败自动切备用 |
| **人格设定** | 人格是"可保存的预设"：写清说话风格和界限，随时切换；改预设立即生效 |
| **聊天水平** | 三个系统提示词方案（聊天 / 角色扮演 / 助手），控制"怎么说话"而不改"你是谁" |
| **会记人** | 长期记忆：常驻画像 + 按需召回，记得住偏好和事实；可关 |
| **看得懂图** | 图片与动图（拆帧）理解，需要模型支持视觉 |
| **会看群、会指代** | 群聊最近动态、谁在说谁、"刚才那条"指什么，能自己查记录 |
| **主动性** | 主动消息（私聊随机 / 群聊沉默后开口，支持免打扰）+ 定时任务（每天 / 每周 / 每月） |
| **用什么工具** | 聊天工具、表情回应、戳一戳、OneBot 全量 API、MCP 外部工具；权限与审批可控 |
| **管理后台** | 浏览器里改配置、看实时日志、看对话、看用量统计；不用改配置文件 |
| **可回滚更新** | 一条命令更新，出问题一条命令退回上一版（含数据库备份） |

## 前置条件

| 依赖 | 要求 |
|---|---|
| **Python** | 3.10 – 3.13，安装时勾选「Add Python to PATH」 |
| **协议端** | NapCat / Lagrange / LLOneBot **任选其一**（本程序通过 OneBot v11 WebSocket 收发消息，**不自带 QQ 客户端**，也不处理 QQ 登录） |
| **网络** | 能访问 PyPI（或已配镜像）；离线环境可用发行包自带的 wheelhouse |

> 只想先确认环境：`python start.py --check` 只做只读检查（不联网、不装包、不启动）。

## 安装与启动

### 方式一：发行包（推荐给不想碰命令行的用户）

1. 从 Release 下载 `QQBotNext-*-kit.zip` 并解压；
2. 运行 `python start.py`（macOS / Linux 用 `./start.sh`）；
3. 首次启动会自动建环境、装依赖、打开浏览器进「首次配置」向导。

包里带 `deploy.json`（逐文件校验）与 `README-FIRST.txt`（三步上手），
**不含** `venv/`、`data/`、`logs/`、`.env`——不会带着别人的数据或 Key。

### 方式二：源码一条命令

```bash
python start.py
```

`start.py` 是一键入口，四步全包：建 venv → 升 pip → 查/装依赖 → 启动。
依赖不齐时它会明确报错并告诉你下一步，而不是甩一屏 `ModuleNotFoundError`。
之后每次启动也只是 `python start.py`。

常用开关：

| 命令 | 说明 |
|---|---|
| `python start.py` | 一键：缺什么补什么，然后启动 |
| `python start.py --check` | 只做只读检查（不联网、不装包、不建 venv、不启动）；退出码 1 = 依赖不齐 |
| `python start.py --no-launch` | 环境备齐但不起进程 |
| `python start.py --recreate` | 删掉重建 `venv`（环境坏掉时的自救入口） |
| `python start.py --dev` | 连带安装开发依赖（pytest / ruff） |
| `python start.py --pause` | 结束前等回车，方便双击运行时看输出 |

> 手动方式：激活 venv → `pip install -e ".[dev]"` → `python main.py`。
> 依赖版本一律以 `pyproject.toml` 为准。

### 首次启动会发生什么

1. 没有 `.env` 就生成一份完整的（全部配置键 + 注释 + 随机令牌）；已存在时只补空令牌，不覆盖你的内容；
2. 初始化 `data/app.db`（SQLite）；
3. 从旧版 JSON 配置自动迁移（迁移后以数据库为准）；
4. 自动连接 `auto_connect=true` 的账号并装配对应模块；
5. 启动管理后台（默认 `http://127.0.0.1:9200`）与定时调度器。

浏览器打开后台，按「首次配置」向导走三步：**添加账号 → 选模型 → 选人格**。

## 把 QQ 接上（协议端）

每个账号可单独选连接方式，两种都是 OneBot v11 WebSocket：

| 方式 | 谁发起连接 | 地址填什么 |
|---|---|---|
| **正向 WebSocket** | 本程序连出去 | 协议端（NapCat / Lagrange / LLOneBot）暴露的 ws 地址，如 `ws://127.0.0.1:3001/` |
| **反向 WebSocket** | 本程序监听，协议端连进来 | 本程序监听地址，如 `ws://0.0.0.0:3001/onebot/v11/ws`；把它填进 NapCat 的「反向 WebSocket」 |

以 NapCat 反连为例：

1. 启动 NapCat 并登录 QQ；
2. 在 NapCat 新建**反向 WebSocket**，地址填 `ws://127.0.0.1:3001/onebot/v11/ws`，Token 与账号里填的一致（或都留空）；
3. 回到本程序「账号管理」新增账号（连接方式选**反向 WebSocket**），点「连接」，NapCat 会自动接入。

> 更省事：访问 `/setup` 向导，第 1 步会创建账号并给出可直接复制的监听地址；连不上时逐步提示
> （对端未接入 / Token 不匹配 / 端口占用）。`access_token` 两种方式都支持。

## 管理后台速览

| 页面 | 干什么 |
|---|---|
| **总览** | 运行状态、就绪检查（差什么、去哪修）、账号状态与诊断台 |
| **账号管理** | 增删账号、连接方式、启停、协议端怎么填 |
| **模型服务** | 连接预设（地址 + Key）+ 模型清单；拉取模型、测连接、给模型标能力（文本/图像/语音/工具调用） |
| **人格设定** | 人格预设的增删改；当前账号用了哪个人格、切过去 |
| **AI 对话面板** | 这个号怎么说话：回复总开关、触发方式、模型池、人格、聊天行为、会话与上下文 |
| **回复与权限** | 谁能让机器人在哪回复：群/私聊范围、响应权限、拥有者与管理者名册、高危工具审批 |
| **功能插件** | 装/卸/启停插件，进入各插件自己的配置页 |
| **高级选项 / 插件响应策略 / 配置包** | 框架级高级开关、多插件同时想回复时的仲裁、一键部署包（导出/导入/回滚） |
| **会话数据 / 数据统计 / 日志 / 设置** | 看历史对话、看用量曲线、看（导出）日志、改后台与安全设置 |

默认情况下：**私聊回复开、群聊回复关**（群聊需要 @ 或关键词才会理，可在「AI 对话面板」「回复与权限」里按群调整）。

## 功能插件一览

框架本体只做"基础能力"（收发消息、会话、tool call、一次 LLM 请求、定时服务）；
讲人话的功能都在插件里，随仓库内置 5 个，按账号开关：

| 插件 | 负责 |
|---|---|
| **触发与调度** | 谁在什么时候开口：主动消息（私聊随机间隔 / 群聊沉默后开口，免打扰时段）+ 定时任务（每天/每周/每月） |
| **上下文增强** | "刚才""那条"指什么；需要时按需展开上下文 |
| **长期记忆** | 记住用户的偏好与事实：常驻画像 + 混合召回 + 后台蒸馏；可关 |
| **工具扩展** | 给模型更多工具（OneBot 全量 API、MCP），并规定它怎么回应工具结果 |
| **LLM 调试** | 把本轮发给模型的完整内容（按层）写进日志，排障用 |

第三方插件放在 `data/module/plugins/<名字>/`（不进仓库，升级不丢），在「功能插件」里安装/启用。
写插件见 [开发者文档](docs/MODULE_DEV.md)。

## 出问题了怎么查

先看**总览页的「运行状态」卡**或访问 `GET /api/readiness`：它会把"差什么、去哪修"逐条列出。

**连上了但不回话**时用**诊断台**（总览「账号状态」每行的听诊器图标）：

- 诊断台里一直没有任何事件 → 问题在协议端（掉线 / 地址填反 / Token 不对）；
- 有事件但不回 → 回复开关、权限、模型配置的问题。

| 现象 | 先查 |
|---|---|
| 群里 @ 没反应 | 群聊回复是否开启、该群是否被单独关闭；「回复与权限」 |
| 私聊不回 | 私聊回复开关；「AI 对话面板」 |
| 有回复但内容空/报错 | 模型池是否为空、Key 是否有效 |
| 账号连不上 | 反向：协议端是否填了同一地址/Token；正向：地址与端口 |
| 启动直接退出 | 退出码 1=venv、2=依赖、3=缺 main.py、4=Python 版本不符（控制台已写明修复命令） |
| 改了配置不生效 | 是否账号级被群级覆盖（「回复与权限」里每项都标来源） |

更多运维细节（日志轮转、备份恢复、端口占用、数据库维护）见 [MAINTENANCE.md](MAINTENANCE.md)。

## 与旧版（v1）的差异

v2 把"一次性脚本"重写成了分层框架：配置从散落的 JSON 收进 SQLite、所有功能拆成可插拔模块、
管理界面换成 Vue 3 + Vuetify 3 的 Dashboard、新增多账号与模型池。
从 v1/v2 早期版本升级时按 `python scripts/update.py` 与迁移脚本提示操作即可。
